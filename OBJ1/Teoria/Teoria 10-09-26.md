<font color="#00b050">Principio de sustitución de liskov: </font>si usamos una clase que es extendida, deberíamos poder usar cualquiera de sus sub-clases  y que el programa sea valido.
<font color="#00b050">Method lookup:</font> cuando un obj recibe un msj y lo busca en su clase un método que corresponda el msj.
Con Herencia: lo mismo pero si no lo encuentra busca en la superclase de subclase y así sucesivamente hasta encontrar o lanzar error.
<font color="#00b050">Overriding:</font> sobre escribir métodos, si una clase tiene un método con mismo nombre de una super, el de la super queda oculto y siempre que le manden el mensaje ejecuta su metodo. En ese metodo puedo hacer algo adicional ademas del heredado llamado igual. 
<font color="#00b050">Super:</font> como .this, hacen referencia al obj que lo ejecuta. Cual uso cambia forma del method lookup, se usa para extender comportamiento heredado.
<font color="#00b050">Super en constructores:</font> si quiero usar comport de otro construc lo invoco usando super.

<font color="#00b050">Clase abstracta: </font> clase que no tiene instancia, tiene variables y metodos. Su funcion es encapsular lo que es comun a sus subclases.
<font color="#00b050">Metodo Abstracto:</font> es un metodo no implementado que debe ser implementado en sus subclases. es decir sub entienden pero no saben q hace.
<font color="#00b050">Tipos/tipado en  OO:</font>  
	• Tipo = Conjunto de firmas de operaciones/métodos (nombre, tipos de argumentos) 
	• Cada clase en Java define un tipo 
	• Cada <font color="#c0504d">interfaz</font> en Java define un tipo 
	• Cuando una clase implementa una <font color="#c0504d">interfaz</font>, es un sub-tipo de ella 
	• Cuando una clase <font color="#c0504d">subclasifica</font> a otra, es un sub-tipo de ella 
	• El tipo de una <font color="#c0504d">variable</font>, es el que indico al declararla
	• El tipo de un <font color="#c0504d">método</font>, es el tipo de lo que retorna
	• El tipo de un <font color="#c0504d">constructor</font>, es la clase que construye
<font color="#00b050">Visibilidad:</font>
	Si declaro una variable de instancia como private en una clase A: 
		• Las instancias de las subclases de A tendrán esa variable de instancia 
		• En los métodos de las subclases de A, no puedo hacer referencia ella 
	• Si declaro un método “m()” como private en una clase A: 
		• Las instancias de sus subclases entenderán el mensaje m() 
		• En los métodos de las subclases de A no puedo enviar m() a ”this“ 
	• Si declaro variables y métodos como protected, puedo verlos en las subclases
